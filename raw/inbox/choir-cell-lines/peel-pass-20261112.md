# Letting peels of fewer than 15 cells pass the edge gate

Run on 2026-11-12, Europe/Vienna. Local folder: `results/analyses/peel_pass_20261112` (git-ignored); protocol,
scripts and outputs are in `peel-pass-scripts-20261112.py.txt`. Follow-up of
`default-tree-third-version-20261112.md`. No production code was changed. Environment: Python 3.12.11, NumPy
2.3.4, SciPy 1.16.3, uv 0.9.5.

## Setup

The code lets a peel of one cell pass the edge gate (`singleton_peel_continuations` in
`tree_break_selection/tree/topology.py`). At run time only, the mapping "peel node -> the child the descent
continues in" was extended: a node whose smaller child has fewer than 15 cells and whose larger child has at
least 15 cells maps to its larger child. The four modules that use the mapping received the extended mapping
(gate evaluator, Tree-BH correction, `fdr_annotation`, `record_collection`). 15 is the smallest number of cells
the reference tests. The edge gate itself, edge alpha 0.001 and the sibling rules are unchanged. The protocol
with five predictions was written before the runs.

Nodes in the extended mapping: default tree 15,847 peels of one cell and 2,112 peels of 2 to 14 cells;
Markov/Ward tree 13,641 and 1,867.

## Reading

- The stop at small peels was the limit of the default tree: with the peel pass the sibling test is called at
  808 nodes instead of 90, the largest cluster falls from 28,611 to 1,990 cells and the ARI rises from 0.0275 to
  0.62 under both rules. 42 lines are recovered; this tree holds 42 of the 190 lines as clean subtrees.
- The default tree stays behind the Markov/Ward tree (ARI 0.62 against 0.87): 87 lines are split and merged,
  45 split only. That is the topology, not the gate.
- Under the peel pass the two rules for k are again close on the default tree (402 and 432 clusters).
- On the Markov/Ward tree the peel pass adds 372 calls and 3 accepted splits, and the ARI rises by 0.0293.
- With the third version the peel pass does not split one Gaussian population in any of the 880 fits.
